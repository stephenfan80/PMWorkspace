# 样例 02：已有功能迭代到交付

这是一个真实匿名风格的公开样例，展示 PMWorkspace 如何处理已上线订阅取消页：先读取生产截图形成 `visual_baseline`，再对齐产品简报、登记原型、复审并交付。

## 匿名背景

某订阅制工具的取消页被用户反馈“暂停”和“取消”含义不清。业务希望减少误取消，但产品、法务和客服都要求取消入口不能被隐藏或弱化。

## 用户输入材料

```text
使用 $pm-workspace 帮我优化订阅取消页。我会提供当前生产截图。
当前问题：用户不理解“暂停”和“取消”的区别。
目标：减少误取消，同时保持取消入口容易找到。
不要改变：账号导航和依法取消入口。
输出：优化后屏幕 + 确认结果页。
```

已提供：生产截图组、必须保留的导航和取消入口说明。
未提供：暂停时长、恢复政策、取消生效时间最终口径。

## 资产流

1. [`product_brief.md`](product_brief.md)：已有功能迭代的产品简报。
2. [`visual_baseline.md`](visual_baseline.md)：生产截图转成可执行视觉基线。
3. [`prototype_manifest.md`](prototype_manifest.md)：登记 3 条优化路径。
4. [`prototype_review.md`](prototype_review.md)：复审是否保护取消入口和线上样式。
5. [`handoff.md`](handoff.md)：交付给设计 / 研发的精简说明。

## 关键 PM 判断

- 目标不是阻止用户取消，而是减少误取消和解释服务状态。
- 取消入口必须容易找到，不能用视觉弱化或流程绕路实现指标。
- 如果后端不支持暂停订阅，不能在原型里展示暂停时长或一键暂停。

## 脱敏边界 / 不能照搬

- 样例截图路径是占位，不代表真实生产图。
- 不能把“暂停”画成确定能力，除非业务和接口已支持。
- 不能因为要降误取消，就隐藏或弱化依法取消入口。
