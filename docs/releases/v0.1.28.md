# AI 产品工作站 / PMWorkspace v0.1.28

本版本把 PMWorkspace 的产品流程控制从“文档规则 + 分散脚本检查”升级为“入口 controller + task revision + preflight 出口许可”的运行时守门。目标是防止旧 run、旧 brief、旧 prototype-board 或旧确认误放行新任务，尤其避免在产品未对齐时直接生成 image-2 原型图。

## 变化

- 新增 `pmw-controller`，提供 `intake`、`next`、`preflight` 和 `stamp`，为每个 PMW 任务生成 `task_digest` 与 `input_revision`。
- 新增 `pmw-image-preflight`，只有当前 run 已通过 prototype preflight 且有合法输出单元时才允许写 image-2 prompt。
- `pmw-dashboard readiness` 默认只读取当前 active run；已完成 run、旧 brief、旧 board 和旧 review 显示为“可参考，不可放行”。
- `pmw-artifact`、`pmw-prototype-board`、`pmw-run` 自动写入当前 `task_digest` / `input_revision` / controller verdict。
- `pm-prototype-shotgun` 出图链路要求先登记当前 task 的 prototype-board 输出单元，再通过 `ALLOW_IMAGE_PROMPT`，未绑定图片只能作为对话附件，不能进入 PMW 原型产物。
- 更新 PMWorkspace 共享契约和所有核心 skill 文档，加入 controller preamble、STOP gate、当前 task revision 绑定和 image preflight 文案。
- 新增 runtime authority eval，覆盖旧 aligned brief、旧确认、旧 board、未 preflight 登图和少于三方案无豁免等违规路径。
