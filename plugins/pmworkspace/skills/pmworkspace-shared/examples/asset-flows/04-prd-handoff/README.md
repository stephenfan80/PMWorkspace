# 样例 04：从转化流程到精简 PRD

这是一个虚构公开样例，展示 PMWorkspace 如何把课程试听报名流程从产品简报、原型清单、复审结论整理成精简 PRD。

## 用户输入

```text
使用 $pm-workspace 为课程试听报名流程生成 3 个移动端方向，对齐后整理成精简 PRD。
用户问题：学员在留下联系方式前，想知道课程是否适合自己的水平。
目标：提升试听预约完成率。
反指标：避免低意向预约和投诉风险。
已知数据：课程等级、课程大纲、老师可约时间、试听片段。
输出：报名页、预约结果页、精简 PRD。
```

## 资产顺序

1. [`product_brief.md`](product_brief.md)：转化流程的已对齐产品简报。
2. [`prototype_manifest.md`](prototype_manifest.md)：登记 3 条转化路径。
3. [`prototype_review.md`](prototype_review.md)：判断推荐方案和待补能力。
4. [`handoff.md`](handoff.md)：读取上游资产生成精简 PRD。

## 关键 PM 判断

- 这不是“把表单做短”这么简单，而是要先给足够价值交换。
- 报名前可展示试听片段和等级匹配，但不能承诺老师立即确认或保证学习效果。
- PRD 只写核心字段：背景、价值、方案、功能、接口数据、埋点、实验、待补充、不可虚构。

## 不能照搬

- 样例里的接口和埋点是占位，需要真实研发确认。
- 不能把缺失接口写成已具备。
- 不能补写测试计划、周期、人力和排期，除非用户明确要求。
