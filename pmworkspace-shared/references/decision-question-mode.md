# 决策选择题模式

PMWorkspace 遇到会改变产品方向、原型范围、实验口径、用户承诺或交付稿的关键点时，默认使用选择题让 PM 拍板。不要只把问题列出来让用户自由发挥。

## 什么时候使用

- 产品方向会分叉：扩大、收缩、转向、先验证或先上线。
- 用户承诺会影响信任：金额口径、覆盖范围、资格条件、数据真实性。
- 原型会明显不同：流程顺序、信息架构、主入口、屏幕数量。
- 实验口径会影响结论：主指标、反指标、入口、样本、线索分发。
- 交付稿仍有待决策项，且不同答案会改变研发或设计执行。

## 输出结构

中文用户使用以下结构：

```text
D1 - <决策标题>
为什么重要：<一句话说明选错会造成什么>
推荐选择：<A/B/C 中的一个>，因为 <一句话理由>

选项 A：<选项名>
- 适合：
- 风险：

选项 B：<选项名>
- 适合：
- 风险：

选项 C：<选项名>
- 适合：
- 风险：

取舍：<这题本质上在权衡什么>
默认假设：如果你不改，我会按 <推荐选择> 继续。
```

## 批次规则

- 一次最多问 3 个选择题。
- 如果待决策超过 3 个，先问最影响产品承诺和原型结构的 3 个；用户回答后再问下一批。
- 不要把多个独立决策塞进同一道题。
- 如果 Codex 原生问题选择工具可用，优先用工具；不可用时使用 Markdown 结构。

## 记录规则

用户回答后，平台脚本可用时记录：

```bash
pmw-log question D1 "<决策标题>" "<推荐选择>" "<用户选择>" "<最终决策摘要>"
pmw-log decision "<决策标题>" "<最终决策摘要>"
```

记录内容必须是脱敏摘要，不写入原始客户材料、token、未脱敏截图或私密 Zoon 正文。

## 示例：通用券拍板问题

```text
D1 - “全品牌可用”的对外口径
为什么重要：口径过大容易形成无条件承诺，用户发现部分品牌不可领时会损害信任。
推荐选择：A，因为它既能表达覆盖面，又保留真实业务边界。

选项 A：参与品牌可领取
- 适合：参与品牌较多，但并非全部在售品牌都有补贴。
- 风险：传播上不如“全品牌可用”强，需要页面解释清楚。

选项 B：全品牌可参与查询
- 适合：希望最大化召回点击，同时把领取结果放到查询后。
- 风险：用户可能觉得只是查一查，领取心智变弱。

选项 C：全品牌都有机会领
- 适合：活动资源非常充足、法务允许高承诺表达。
- 风险：如果实际覆盖不足，投诉和信任损耗最大。

取舍：增长吸引力 vs 承诺真实性。
默认假设：如果你不改，我会按 A 继续。

D2 - 至高金额展示方式
为什么重要：金额口径会影响点击率、信任感和后续解释成本。
推荐选择：A，因为统一上限最适合首轮召回实验。
选项 A：统一至高金额
选项 B：按城市动态展示
选项 C：按品牌/活动动态展示
取舍：传播简单 vs 个性化准确。
默认假设：如果你不改，我会按 A 继续。

D3 - 多车提交后的线索生成
为什么重要：线索分发规则会直接影响经销商接单、归因和用户骚扰风险。
推荐选择：A，因为它匹配用户已拍板的“一车一线索”业务规则。
选项 A：每个车系生成一条线索，第一个车正常分发，剩余车系 1 分 1
选项 B：只生成一条线索，携带多个意向车
选项 C：先生成主车线索，结果页再引导补充其他车
取舍：线索覆盖 vs 分发复杂度和打扰风险。
默认假设：如果你不改，我会按 A 继续。

D4 - 首轮主实验入口
为什么重要：入口会决定用户意图强弱、样本质量和活动心智。
推荐选择：A，因为站内搜索和站外召回能同时覆盖强意图和沉睡用户。
选项 A：站内搜索 + 站外投放召回
选项 B：只做站内搜索
选项 C：只做站外投放召回
取舍：实验覆盖面 vs 归因复杂度。
默认假设：如果你不改，我会按 A 继续。

D5 - 质量护栏指标
为什么重要：只看线索量会把低意向广撒网误判为增长。
推荐选择：A，因为它同时看独号转化和线索质量。
选项 A：独号转化率 + 线索质量
选项 B：独号率 + 有效接通率 + 经销商拒收/投诉
选项 C：线索量 + 成本优先
取舍：增长速度 vs 真实成交质量。
默认假设：如果你不改，我会按 A 继续。
```
