# 资产流样例总览

本目录展示 PMWorkspace 面向用户可理解的四条完整资产链。每条链都采用真实匿名风格：业务背景、输入材料、证据边界、产品判断、出图约束、复审结论和交付缺口都像真实项目一样写清楚，但不包含真实客户、真实截图或内部数据。

## 资产顺序

| 顺序 | 资产 | 用户怎么理解 |
|---|---|---|
| 1 | `product_brief.md` | 已对齐产品简报，回答为什么做、做什么、不做什么、不能承诺什么。 |
| 2 | `visual_baseline.md` | 线上截图 / 视觉参考基线；没有生产截图时也保留资产位，明确写“不适用 / 使用默认移动端基线”。 |
| 3 | `prototype_manifest.md` | 原型清单，记录每个方案、屏幕、目标、反指标、不可虚构边界和生成状态。 |
| 4 | `prototype_review.md` | 原型复审结论，判断可通过、需要重出、需要补参考或需要 PM 拍板。 |
| 5 | `handoff.md` | 产品设计文档、精简 PRD 或研发交付稿。 |

## 四条样例

| 样例 | 说明 | 重点 |
|---|---|---|
| [`01-new-idea`](01-new-idea/) | 从“习惯匹配”新想法到产品设计文档。 | 新想法如何先做产品判断，没有生产截图时如何记录 baseline 不适用。 |
| [`02-existing-feature`](02-existing-feature/) | 从订阅取消页生产截图到优化交付。 | 已有功能必须先有视觉基线，不能隐藏取消入口。 |
| [`03-screenshot-iteration`](03-screenshot-iteration/) | 根据标注截图改一张已生成原型。 | 只改指定区域，产品承诺变化必须回写 brief；局部重出可豁免三方案。 |
| [`04-prd-handoff`](04-prd-handoff/) | 从课程试听报名流程到精简 PRD。 | PRD 读取 brief、baseline、manifest、review，不虚构接口和埋点。 |

## 每个样例 README 的固定结构

- 匿名背景：说明这是哪类业务和哪类用户问题。
- 用户输入材料：列出用户给了什么、没给什么。
- 资产流：按 `product_brief` -> `visual_baseline` -> `prototype_manifest` -> `prototype_review` -> `handoff` 阅读。
- 关键 PM 判断：说明这个样例最值得学的产品取舍。
- 脱敏边界 / 不能照搬：说明哪些字段只是公开样例，不能当成真实能力。

## 阅读方式

先读每个样例目录的 `README.md`，再按资产顺序阅读。样例中的图片路径、数据、指标、用户和业务背景都是公开脱敏示意；真实项目必须读取当前 run 的本地资产、Zoon 快照、截图和用户确认。
