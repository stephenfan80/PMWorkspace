# 自动产品评审流水线

`$pm-autoplan` 使用本文件。目标是把 PMWorkspace 从“用户手动选择下一个 skill”升级为“自动识别当前最早缺口，并只在关键产品取舍处停下”。

## 流水线

```text
输入识别
-> 工作目标模式
-> 场景路由
-> Q 诊断缺口
-> 前提确认
-> D 拍板
-> 策略审查
-> 产品简报
-> Zoon 同步
-> Zoon 漂移检查
-> 原型准备度
```

## 自动推进边界

可以自动推进：

- 用户材料已经明确回答的问题。
- 不改变产品方向的默认格式、画布和字段。
- 已有 Zoon URL 时优先追加，不创建新文档。
- 已有产品简报且用户要求继续时，先做漂移检查。

必须停止：

- 缺少会改变产品结构的事实。
- 缺少会改变范围、承诺、实验口径或数据边界的决策。
- 线上参考需要但缺失。
- Zoon 最新内容与本地 brief 不一致。
- 产品简报不是 `已对齐`，但用户要求出图或交付。

## 完成态

- `需要补充`：必须先拿输入或参考。
- `待确认`：已有推荐和假设，等待用户确认。
- `已对齐`：产品简报可以作为事实来源。
- `可进入原型复审`：已生成图片，下一步应走 `$pm-prototype-review`。

## 输出原则

- 不批量展开多个 `D`。
- 不用长开放问题清单替代下一步。
- 不把自动判断包装成用户已确认的事实。
- 如果自动创建或追加 Zoon 失败，保留本地 brief 并把失败原因写进状态。
