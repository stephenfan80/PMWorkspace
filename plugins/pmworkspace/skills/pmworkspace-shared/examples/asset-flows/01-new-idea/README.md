# 样例 01：新想法到产品设计文档

这是一个真实匿名风格的公开样例，展示 PMWorkspace 如何处理一句新想法：先对齐产品判断，再登记三条产品路径原型，复审后输出产品设计文档。

## 匿名背景

某移动健康类产品想验证“习惯匹配”新功能。团队只有目标、可用时间和历史打卡数据三个输入，不确定应该先强调快速开始、推荐可信度，还是先让用户排出真实时间。

## 用户输入材料

```text
使用 $pm-workspace 帮我判断“习惯匹配”这个新功能应该怎么推进。
用户想建立运动习惯，但不知道哪个计划适合自己的时间安排。
目标：提升第一周计划激活率。
已知约束：只有时间安排、目标和历史打卡数据可用。
输出：3 个移动端原型方向，每个方案单独出图。
```

未提供：生产截图、现有页面、推荐规则阈值、历史打卡口径。

## 资产流

1. [`product_brief.md`](product_brief.md)：把一句想法收敛成已对齐产品简报。
2. [`visual_baseline.md`](visual_baseline.md)：没有生产截图时，记录参考基线不适用和默认移动端约束。
3. [`prototype_manifest.md`](prototype_manifest.md)：登记 3 条产品路径和单图输出单元。
4. [`prototype_review.md`](prototype_review.md)：复审原型是否忠实表达 brief。
5. [`handoff.md`](handoff.md)：把推荐方案整理成产品设计文档。

## 关键 PM 判断

- 用户不是缺一个“更聪明的计划库”，而是缺一个能把目标和真实可用时间连接起来的第一周开始方式。
- 本轮原型只验证激活路径，不承诺健康结果、可穿戴设备同步或 AI 教练聊天。
- 3 个方案必须在产品路径上不同：快速推荐、信任解释、先排时间。

## 脱敏边界 / 不能照搬

- 不能把样例里的数据字段当成真实可用能力。
- 不能把“推荐计划”画成确定医学、健身或健康承诺。
- 不能把 3 个方案简化成同一页面的 3 种配色。
