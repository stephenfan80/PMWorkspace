PMWorkspace 的解法
不是帮你跳过思考，
而是把思考压缩成路径

PMWorkspace 不是一个聊天框，而是一支 AI 产品小队。它有结构、有记忆、有流程——把散乱的输入收束成可以继续流动的产品资产。

  • ✓ 先判断真实问题，再出方向——不会把功能愿望当解法
  • ✓ 把散乱材料收束成共识——想法、截图、PRD、协作文档压缩成一份能继续流动的简报
  • ✓ 出图前有证据——线上参考、视觉基线、状态页不再只是口头描述
  • ✓ 多角色评审补盲区——策略、信任风险、设计系统、数据可行性四视角联合把关
  • ✓ 产物往下游流动——产品决策沉淀为资产，下次不用重新讲
和直接用 AI 有什么不同

不只是更快，
而是一套会成长的产品工作系统

直接对话 AI 能帮你生成内容，但它不记得你、不懂你的产品、没有流程约束、不积累资产。PMWorkspace 从根本上不同。

直接用 AI 对话
  • 每次从零开始，没有你的上下文
  • 你问什么答什么，不质疑问题本身
  • 快速生成原型，不管问题有没有想清楚
  • 单一视角，容易漏掉策略和风险盲区
  • 对话结束即消失，决策没有沉淀
  • 不记得你的偏好、历史决策、产品风格
  • 每次交付都要重新解释上下文
VS
PMWorkspace
  • 资产积累——简报、决策、偏好持续沉淀，越用越懂你
  • 先判断真实问题，再出方案，不跳过思考环节
  • 有门槛才出图——简报未对齐时不生成原型
  • 多角色评审军团——策略、风险、设计、数据四视角把关
  • 产物往下游流动——简报、原型、PRD 形成完整链路
  • 越用越懂你——沉淀产品品味、认知框架和历史决策
  • 下次不用重新讲——项目记忆随时可调用

你能拿到什么

具体的产品资产，不是聊天记录

每一次工作流的结尾，你得到的是可以继续用的东西——不是对话截图。

产品简报
可对齐的共识文档
目标用户、核心问题、当前损失、反指标、约束和不可虚构项，压缩成一份所有人看同一份的材料。
方案方向
真正有差异的解法
在产品策略、信息架构、交互模型或信任模型上不同，不只是换配色的"多版本"。
移动端原型
一方案一屏一张图
默认按 iPhone 17 竖屏生成 image-2 原型图。一个方案、一个屏幕、单独一张图，清晰可判断。
交付文档
可直接用的 PRD
通过评审后整理成精简 PRD、设计交付、实验验证或研发交付材料，保留接口、数据、埋点和实验标准。
工作方式

像一支产品小队，不是问答机器

每一步都有明确的进入条件和产出标准，不会在错误的问题上快速出图。

01
判断真实问题

每次只问最关键的问题，最多 5 轮。先说清"我对真实问题的判断"，避免把功能愿望当解法。

动态诊断提问
策略评审 & 前提确认
拍板选择题减少反复
02
对齐 & 生成方案

产品简报对齐后，生成多个方向和移动端原型图，并纳入线上截图证据和协作文档。

产品简报 → Zoon 同步
2–3 个差异化方案方向
每方向 1 张 image-2 原型
03
评审 & 交付

四视角联合评审，产出通过 / 重生成 / PM 决策三种结论，最终整理成可直接进入评审的交付文档。

策略 + 风险 + 设计 + 数据
PRD / 设计 / 实验 / 工程稿
产物沉淀供下游复用
核心优势

不是"更快的 AI"，是更结构化的产品工作方式

01
快，但不莽
快速成型 10 分钟起步，但必须带假设、反指标和不可虚构项。速度不等于失控。
"可以先基于假设推进，但出图前必须确认这些假设。"
02
把散乱材料收束成共识
想法、PRD、截图、协作文档、用户洞察——无论你带来什么，都会被压缩成一份能继续流动的产品简报。
再也不用在评审现场重新解释"这个需求从哪里来"。
03
出图前有证据
线上参考、视觉基线、状态页和竞品流程不再只是口头描述，统一登记为可复用的线上证据产物。
设计同学再也不会拿到一张"没有线上参考"的原型。
04
评审不只靠一个视角
原型复审默认有策略、信任/风险、设计系统、数据可行性四个专家视角，高风险场景还能追加更多角色。
把评审时才发现的问题，提前到出图前发现。
05
产物往下游流动
产品简报、原型清单、复审结论和交付稿被登记为下游可读产物。产品决策沉淀成资产，不靠记忆传递。
下一次类似项目，你能找到"当初为什么这么决策"。
06
有记忆，但不越界
可以沉淀你的产品偏好和历史决策，但不会用偏好覆盖本轮的事实、风险或用户确认，隐私边界清晰。
token、客户资料、内部录音、未脱敏文档不写入公开材料。
两种工作模式

按你现在的状态选择入口

想法还很模糊？快速成型。已有 PRD 或需要对外交付？深度交付。

快速成型
想法 → 方案包 最快 10 分钟

适合新想法、组内讨论、领导预览或创业验证。带着假设出发，快速得到可以讨论的东西——而不是一直在"想清楚再动"。

  • 2–3 个关键澄清，补齐最大缺口
  • 产品简报（明确标注假设）
  • 2–3 个方案方向（策略/架构/交互各维度不同）
  • 每个方向 1 张移动端原型图
  • 下一步建议：验证 / 评审 / 升级交付
⚡ 10 分钟起步，不等想法"完全想清楚"
深度交付
PRD → 交付就绪 诊断驱动，端到端

适合 PRD 交付、设计评审、研发排期或需要协作文档对齐的项目。只有简报达到"已对齐"状态，才进入出图或交付——避免在错误方向上快速推进。

  • 动态诊断 + 策略评审 + 拍板选择题
  • 产品简报 ↔ Zoon 协作文档双向同步
  • 线上截图证据纳入工作流
  • 四视角 PM 评审军团把关原型
  • PRD / 设计 / 实验 / 工程 交付文档

添加到 Codex Plugin

公开上架前，先用 GitHub marketplace 安装

AI 产品工作站暂未进入默认插件市场。按下面步骤添加后，在 Codex 的 Plugins 页面切到“全部”即可搜索到。

Step 01 · Terminal
运行一条命令添加 marketplace

首次安装直接运行：

$ codex plugin marketplace add stephenfan80/PMWorkspace

如果你之前添加过旧版本或本地路径，先移除再添加：

$ codex plugin marketplace remove pmworkspace $ codex plugin marketplace add stephenfan80/PMWorkspace
Step 02 · Codex UI
重启 Codex，然后在插件页启用
  • 1 完全退出并重启 Codex，让 marketplace 缓存刷新。
  • 2 打开 Plugins，把筛选从 Built by OpenAI 切到 全部。
  • 3 搜索 AI 产品工作站 或 PMWorkspace，点击安装 / 启用。
  • 4 新开对话，输入 使用 $pm-workspace 帮我选择产品工作流。
公开插件库正式上架后，普通用户可以直接在 Codex 插件页搜索安装；GitHub marketplace 是当前 beta 和团队测试路径。
