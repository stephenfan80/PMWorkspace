# 自动产品评审流水线

`$pm-autoplan` 使用本文件。目标是把 PMWorkspace 从“用户手动选择下一个 skill”升级为“自动识别当前最早缺口，并只在关键产品取舍处停下”。它支持两个入口：快速成型和深度交付。

## 模式选择

- **快速成型：** 用户有一句 idea、拍脑袋方案、想先看几个方案、想要 10 分钟轻量包，或输出目标是“产品简报 + 方案方向 + 原型图”。目标是快速产出可讨论资产。
- **深度交付：** 用户要 PRD、设计评审、研发交付、Zoon 协作、生产截图迭代、线上流程或高风险业务。目标是沉淀可交付事实来源。

多个信号并存时，优先识别用户当前要解决的最近任务：如果是“先拿出去讨论”，选快速成型；如果是“要交付给下一团队”，选深度交付。

## 快速成型流水线

```text
输入识别
-> 2-3 个关键 Q
-> 假设确认
-> 轻量产品简报
-> 2-3 个方案方向
-> image-2 原型图计划
-> 下一步升级建议
```

快速成型的轻量包必须包含：

- 产品简报：标注 `基于假设，可讨论`，列出当前假设、主目标、反指标和不可虚构项。
- 方案方向：2-3 个方向，差异必须来自产品策略、信息架构、交互模型或信任模型。
- 原型图计划：每个方案默认 1 张移动端图；每张图绑定方案名、屏幕任务、主目标、反指标、不可虚构项和简报版本。
- 升级建议：继续补齐 PRD、进入原型复审，或整理成设计/研发交付稿。

快速成型出图前必须让用户确认：`按这些假设继续`。确认前只能输出轻量包计划，不能生成图片。

## 深度交付流水线

```text
输入识别
-> 工作目标模式
-> 场景路由
-> Q 诊断缺口
-> 前提确认
-> D 拍板
-> 策略审查
-> 产品简报
-> Zoon 同步
-> Zoon 漂移检查
-> 原型准备度
```

## 自动推进边界

可以自动推进：

- 用户材料已经明确回答的问题。
- 不改变产品方向的默认格式、画布和字段。
- 已有 Zoon URL 时优先追加，不创建新文档。
- 已有产品简报且用户要求继续时，先做漂移检查。
- 快速成型模式中的轻量包默认结构和默认移动端画布。

必须停止：

- 缺少会改变产品结构的事实。
- 缺少会改变范围、承诺、实验口径或数据边界的决策。
- 线上参考需要但缺失。
- Zoon 最新内容与本地 brief 不一致。
- 深度交付模式中，产品简报不是 `已对齐`，但用户要求出图或交付。
- 快速成型模式尚未获得用户确认“按这些假设继续”，但即将生成图片。

## 完成态

- `需要补充`：必须先拿输入或参考。
- `待确认`：已有推荐和假设，等待用户确认。
- `基于假设，可讨论`：快速成型轻量包已经确认，可用于讨论，但不是最终 PRD 或已验证事实。
- `已对齐`：产品简报可以作为事实来源。
- `可进入原型复审`：已生成图片，下一步应走 `$pm-prototype-review`。

## 输出原则

- 不批量展开多个 `D`。
- 不用长开放问题清单替代下一步。
- 不把自动判断包装成用户已确认的事实。
- 如果自动创建或追加 Zoon 失败，保留本地 brief 并把失败原因写进状态。
