# 样例 03：截图反馈迭代

这是一个虚构公开样例，展示 PMWorkspace 如何根据标注截图修改已生成原型：先判断反馈类型，再只重出受影响单图，避免把局部设计反馈误当成产品承诺变化。

## 用户输入

```text
使用 $pm-prototype-shotgun 根据我的标注截图修改这个原型。
红框表示删除表单页里的解释模块。
绿框表示只保留手机号和主要按钮。
产品意图是否改变：否。
输出：优化后表单页 + 对应结果页。
```

## 资产顺序

1. [`product_brief.md`](product_brief.md)：确认本轮反馈不改变产品意图。
2. [`visual_baseline.md`](visual_baseline.md)：记录标注截图、可改区域和保留区域。
3. [`prototype_manifest.md`](prototype_manifest.md)：登记受影响单图和结果页补充策略。
4. [`prototype_review.md`](prototype_review.md)：判断是否只需重出当前屏。
5. [`handoff.md`](handoff.md)：沉淀修改说明和交付边界。

## 关键 PM 判断

- 红框和绿框只改变表单页的信息密度，不改变产品承诺。
- 如果删除解释模块会影响用户理解，结果页或下一步说明需要补足，但不能新增后端能力。
- 只有受影响单图需要重出，不重出已通过的其他方案。

## 不能照搬

- 不能把“删解释”理解成“产品不需要解释价值”。
- 不能把局部 UI 修改扩展成完整 PRD 重写。
- 不能新增手机号校验、智能匹配或结果承诺，除非 brief 已确认。
