# 产品发现硬门槛

产品发现不是“一问一选后进入简报”，也不是把用户的功能名改写成方案后直接出图。它必须先经过产品方向审查内核：`前提挑战 -> 现状替代 -> 不做推演 -> 路径对比 -> 范围模式 -> 当前拍板`，再进入产品简述确认和三条产品路径计划。

`Q` / `D` 只作为关键卡点的交互方式：缺事实时问 `Q`，方向、范围、承诺或实验口径会改变时问 `D`。Agent 在提问前可以先协助用户完成材料整理、线上截图判断、截图结构拆解、访谈提纲、需求假设表、数据口径梳理、最佳实践检索和路径对比。

## 必须覆盖的 5 个事实维度

深度交付、现有线上功能优化、线索 / 交易 / 价格 / 结果页等高风险场景，必须覆盖以下维度后才能生成或确认产品简报：

- `product_role`：产品定位与链路角色。这个能力在链路中负责决策、解释、信任、转化还是交付。
- `target_trigger`：目标用户与触发场景。谁在什么时刻需要这个能力。
- `current_alternative`：用户现状与当前替代。用户今天如何判断、绕路、咨询、等待、比价或放弃。
- `pain_loss`：真实痛点与当前损失。现状造成困惑、时间成本、金钱风险、信任损耗、转化流失还是客服压力。
- `goal_countermetric`：主目标与反指标。要改善什么，同时不能牺牲什么。

如果任一维度缺失，当前门槛就是 `产品发现深度不足`。下一步应回到对应任务：补证据、整理数据、生成访谈提纲、拆解截图，或在确实需要用户判断时处理产品作业卡里的当前主阻断；不能进入产品简述确认、image-2 prompt 或交付。

缺口、阻断、纠偏或产品作业描述不能反向充当事实证据。比如“尚未完成产品定位、目标用户、当前替代、真实损失和反指标”只能证明这些维度缺失，不能被 `pmw-discovery-gate` 识别为已覆盖；“已确认北极星”也不能自动算作方向性 `D`。事实维度应通过结构化产品简报内容或 `pmw-log discovery --dimension ...` 记录，方向性取舍应通过明确的 `D` 问题或 decision 记录。

## 产品信息对齐优先

产品发现硬门槛的执行形态是 `产品作业卡`，不是分散问题清单。PMW 每次进入产品简报或原型计划前，必须先把已知事实、暂定判断、证据边界、当前主阻断、关键缺口队列、产品判断对抗校验、PMW 产品建议、PMW 信息架构建议和用户作业收束到同一处。

如果作业卡显示任一核心事实维度缺失，用户可见输出只能停在当前主阻断、关键缺口队列、PMW 可协助事项和产品作业；不能用“方案方向”“三条路径”“推荐方案”来绕开事实缺口。

如果用户提到已有页面、当前链路、其他页面、竞品平台或线上替代路径，作业卡必须把 `线上 / 竞品基线` 放进关键缺口队列。它是证据请求，不是方向 `D`：先要求当前线上截图、关键节点截图、线上 URL、Figma / 设计稿，或竞品截图、URL、可借鉴点；再继续当前 Q/D 或产品简报确认。

已有功能缺线上基线时，`pmw-discovery-gate check --target brief` 可以允许保存 `待确认` 产品简报，但不能允许声明 `已对齐`，也不能进入三条原型路径、image-2 prompt 或交付稿。竞品参考缺失不默认阻断待确认 brief，但如果用户主动提到竞品平台，必须在待确认问题卡或产品作业卡里要求补截图、URL 或具体可借鉴点。

已有功能迭代尤其要先完成线上基线接收。缺截图、关键节点截图或等价视觉基线时，不得输出 `方案 A / 方案 B / 方案 C` 这类看似已成型的方案，只能输出：

- 当前业务判断。
- 为什么缺线上基线会影响问题区域、保留项、可改项和原型可信度。
- 用户需要补的线上截图、关键节点截图、线上页面 URL、Figma / 设计稿或数据。
- Agent 拿到材料后会如何拆解。
- 补齐后解锁的下一步。

可以列“待评估角度”，但必须显式写成假设和风险，不能命名为产品方案或原型方向。

## 已有功能迭代的事故门槛

已有线上功能优化不能把“用户选了一个方向”理解成产品已经对齐。方向选择只说明用户愿意沿某条产品路径继续探索，不代表 PMW 可以跳过截图拆解、当前问题确认、保留 / 可改边界和产品简报确认。

当用户在一个方向 `D` 之后补充线上截图、关键节点截图或视觉基线时，必须先进入 `线上基线接收`：

- 先承认上一轮 `D` 只确认了方向，不是产品简报已对齐。
- 从截图中提炼当前线上结构、已有优势、当前问题区域、必须保留项、可改项和不应改项。
- 明确新方案要赢过当前线上方案的证据或判断；如果说不清为什么会更好，先不出图。
- 缺当前功能数据 / 业务现状时，可以假设驱动继续，但必须写 `数据佐证：未提供，本方案存在未验证风险`。
- 产品简报确认前，只能输出基线拆解、待确认前提、一个当前 `Q` 或一个当前 `D`；不能写 image-2 prompt、不能调用 image-2、不能把截图后的新想法包装成已验证方案。

已有功能迭代默认不允许用 `1 个方向 D` 豁免产品发现深度。至少还要确认当前问题区域、保留项 / 可改项、主目标、反指标和不可虚构项；缺任一项时，下一步是 `$pm-jobs` / `$pm-brief`，不是 `$pm-prototype-shotgun`。

## 产品判断对抗校验

进入产品简述确认或原型计划前，`$pm-jobs` 必须先挑战当前产品判断是否站得住。这个校验不是新增流程，而是产品方向审查内核的一部分，用来防止把用户的功能愿望、Agent 的推断或证据不足的假设包装成确定方案。

每轮产品评估都要输出并写入审计：

- `我担心的想当然`：用户或 Agent 目前默认相信了什么，但证据还不够。
- `可能的理解偏差`：用户原始诉求和 PMW 重新定义的问题之间可能偏在哪里。
- `证据不足处`：目标用户、触发场景、当前替代、当前损失、主目标、反指标或不可虚构项中哪一项缺证据。
- `需要降级为假设的判断`：哪些说法只能写成假设驱动，不能写成已验证需求。
- `建议继续 / 收缩 / 转向 / 补证据`：当前推荐动作，以及它会影响产品简报、原型范围或下一步产品作业的哪一部分。

如果对抗校验发现真实问题、当前替代或当前损失不成立，不能直接进入 `$pm-brief`。如果只是证据不足但用户选择按假设推进，可以继续生成待确认产品简述，但必须标记 `假设驱动`，并把假设、证据缺口和理解偏差风险写入产品简报。

## 发现维度与决策门槛映射

以下门槛是产品发现的最小判定面，不再维护独立决策门槛文档：

- `产品路径`：先判断全新功能、已有功能迭代，或线上流程承接；已有功能迭代必须有当前线上截图、关键节点截图或等价视觉基线。
- `问题真实性`：说明用户问题、当前替代方案和证据强度；证据不足时标记为假设，不能包装成已验证事实。
- `产品判断对抗校验`：指出当前最可能的想当然、理解偏差、证据不足处和需要降级为假设的判断；不能只顺着用户想法补全方案。
- `不做推演`：说明本周期不做的真实损失；损失不清时不能包装成强需求。
- `路径对比`：进入范围模式前至少给最小路径和增强路径；复杂方向补充收缩 / 转向路径。
- `范围模式`：选择扩大、选择性扩大、保持、收缩或转向；改变范围、承诺、实验或交付责任时必须进入一个 `D`。
- `目标与反指标`：定义主行为 / 主指标，同时定义不能变差的信任、质量、投诉、留存、任务成功率、成本或合规护栏。
- `价值交换`：手机号、注册、付款、授权、预约、安装或长流程设置等高成本动作，必须说明行动前用户先得到什么、行动后什么会变好。
- `数据与可行性`：区分可用、估算、推断、用户提供、人工、合作方和不可用数据；不可交付能力不能出现在原型承诺里。
- `场景策略`：确认主场景路由和原型形态；多方案任务在生成图片前，先确认方案差异来自产品策略、信息架构、交互模型或信任模型。
- `产品简述对齐`：用户确认短版产品简述 / 产品简报、批准假设或更新事实来源前，不能进入 image-2 prompt、出图或交付。
- `线上参考`：线上流程下一步、结果页、状态页、活动承接页或生产样式继承场景，必须有线上截图、关键节点截图、相似页面或线上页面 URL，或明确记录“无线上参考已确认”。

## Q 与 D 的分工

- `Q` 补事实：用户是谁、触发时刻、当前替代、真实损失、指标、约束。
- `D` 拍取舍：产品定位 / 范围、价值交换 / 信任承诺、数据承诺 / 转化动作、实验口径。
- `D` 不能替代事实诊断；一个 `Q` 加一个 `D` 不能代表产品发现完成。
- 用户选择 `方案 A / 方案 B / 方案 C` 只能算 `方案方向确认`，不能算 `产品简报确认`；尤其在用户随后上传截图时，必须重新把截图事实写入 brief 并等待用户确认。
- 不得把“只问一个 Q 或一个 D”写成产品发现的完整流程；当前卡点如果是前提挑战、现状替代、不做推演、路径对比、材料整理、证据收集、截图分析、数据梳理或访谈准备，就先完成该任务。
- 最终确认产品简报前，深度交付默认至少需要 2 个方向性 `D`。若只有 1 个 `D`，必须记录 `D 豁免原因`；现有线上功能优化默认不豁免。

## 平台记录

可用时用以下命令记录已确认的产品发现维度：

```bash
pmw-log discovery --dimension product_role --source "用户回答 / 截图 / Zoon / 数据" --summary "<事实摘要>" --confidence confirmed
```

候选产品简报声明 `确认状态：已对齐` 前，必须运行：

```bash
pmw-discovery-gate check --target brief --brief <brief.md>
```

如果返回 `blocked`，只能保存 `待确认` 简报或继续 `$pm-jobs`，不能写 image-2 prompt、不能出图、不能交付。
