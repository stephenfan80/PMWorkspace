# PM Review Army

PM Review Army 是结构化多视角复审协议。v1 不要求真实多 agent 并行，但必须让不同角色独立暴露盲区，再合并成行动建议。

## 默认 reviewer

- **策略专家**：检查目标用户、核心问题、价值交换、范围取舍是否成立。
- **信任 / 风险专家**：检查反指标、不可虚构项、数据承诺、隐私和用户预期。
- **设计系统专家**：检查生产样式、信息层级、组件合理性、可读性和移动端可用性。
- **数据可行性专家**：检查页面展示的数据、自动化能力、资格判断和计算口径是否可兑现。

## 合并结论

每个 reviewer 的问题最终必须合并成三类：

- `可通过`：问题不影响产品判断或交付使用。
- `需要重出`：图片或方案违反简报、反指标、不可虚构项、线上参考或设计系统。
- `需要 PM 拍板`：问题来自产品取舍未决，不应靠改图解决。

合并时使用最高严重度，而不是平均分：任一 reviewer 发现不可虚构违规、反指标风险、线上参考偏离或设计系统实质偏离，结论至少是 `需要重出`；任一 reviewer 发现用户承诺、数据真实性、范围、实验口径、线索/交易/隐私/合规边界未决，结论至少是 `需要 PM 拍板`。

只有所有 reviewer 的问题都只是轻微文案、局部密度、对齐或审美偏好时，才允许 `可通过` 并把偏好写入 taste。

## 输出格式

```text
PM Review Army：
- 策略专家：
- 信任 / 风险专家：
- 设计系统专家：
- 数据可行性专家：
- 合并结论：
- 需要重出：
- 需要 PM 拍板：
```

复审的目标不是证明方案没问题，而是用最低成本暴露“现在交付会误导谁”。
