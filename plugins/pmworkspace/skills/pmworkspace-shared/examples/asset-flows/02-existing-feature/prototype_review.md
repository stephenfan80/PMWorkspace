# prototype_review：订阅取消页优化

复审目标：检查原型是否保留生产视觉基线、保护取消入口，并且没有把不存在的订阅能力画成已支持。

## 总 verdict

需要小修后可通过。推荐采用 **方案 A：差异解释前置**，并把方案 B 的结果页状态说明作为第二屏。方案 C 只有在暂停时长和恢复规则确认后才能进入交付。

## 策略复审

- 通过：A 直接解决“暂停和取消差异不清楚”的主问题。
- 通过：B 补齐取消后状态，能降低客服咨询。
- 阻断：C 依赖暂停能力和规则，未确认前不能写入验收。

## 信任 / 风险复审

- 通过：取消入口仍在原位置附近可见。
- 需修正：暂停按钮不能比取消按钮强到让用户误以为取消不可用。
- 禁止：不允许新增折扣、客服回访或价格保留承诺。

## 设计系统复审

- 通过：沿用生产页按钮、字号和模块密度。
- 需小修：新增解释模块的间距应贴合生产页，不要像外部活动卡。

## 数据可行性复审

- 已具备：订阅状态、价格、到期时间。
- 待确认：暂停时长、恢复方式、取消生效时间。
- 不可写入验收：任何价格保留、退款或优惠承诺。

## 交付建议

进入 `$pm-handoff` 生成精简交付稿。验收标准只写 A 和 B 已确认能力；C 暂停路径列为待确认，不作为首版验收。
