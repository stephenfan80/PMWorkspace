# PM 自动决策原则

本文件把 PMWorkspace 的自动推进边界从分散规则升级为共享决策协议。目标是少问不重要的问题，但绝不跳过会改变产品事实、用户承诺或原型结构的判断。

## 事实优先级

当多个来源冲突时，按以下顺序判断：

1. `已对齐` 的产品简报或最新 Zoon 快照。
2. 用户本轮明确输入、截图、录屏或 URL 证据。
3. 当前对话中已经确认的 Q / D / 前提。
4. 本地运行审计、方案比较板和原型复审结论。
5. 历史偏好、taste 记忆和产品 learning。

历史偏好只能影响推荐方式，不能覆盖当前 brief、Zoon、反指标、不可虚构项或线上参考门槛。

## 可以自动采用

这些项可以自动推进，但要在输出中写入“已自动采用”或运行审计：

- 用户材料中已经明确写出的事实。
- 无线上截图时可自动采用 `standard_first_screen` 模板；有线上截图 / `visual_baseline` 时不能自动套用标准模板，必须使用 `physical_longboard` 模板和截图物理长板。
- 不改变产品方向的字段、标题、状态格式和输出结构。
- 已有 Zoon URL 时优先 append，不新建文档。
- 快速成型模式中的默认轻量包结构和默认图片数量。
- 低风险、可逆、不会改变用户承诺或数据边界的表达优化。

## 必须停止并提问

这些项必须停下，用 `Q` 诊断或 `D` 选择题处理：

- 目标人群、主目标、反指标或不可虚构项缺失，并会改变产品简报或原型结构。
- 多方案方向没有本质差异，只是配色、圆角、插画或视觉皮肤不同。
- 线上参考需要但缺失，且用户没有确认“没有线上参考，按新页面概念稿推进”。
- Zoon 最新内容和本地产品简报冲突。
- 用户承诺、数据真实性、范围、实验口径、线索分发、交易、隐私或合规边界需要 PM 拍板。
- 快速成型模式尚未获得用户确认“按这些假设继续”，但即将生成 image-2 图片。

## Q / D 选择

- `Q` 用于发现事实：用户、问题、现状替代、主目标、反指标、约束、数据和不可虚构项。
- `D` 用于选择取舍：承诺口径、原型范围、实验口径、方案方向、线索/交易/隐私边界。
- 如果信息不足以形成有意义的选项，先问 `Q`，不要用 `D` 掩盖缺失事实。
- 如果不同选项不会改变产品方向、用户承诺或交付执行，不要制造 `D`。

## 偏好与记忆边界

应用历史偏好时必须满足：

- 明说“基于过往偏好，我建议……”，不要把偏好包装成事实。
- 如果偏好和当前 brief、Zoon、反指标或不可虚构项冲突，以当前事实来源为准。
- 用户拒绝过的方案方向，不要在下一轮作为“新方案”重新推荐。
- 重复出现的用户反馈可以沉淀为 learning，但必须脱敏、短摘要化，并标注适用边界。

## 审计要求

平台脚本可用时：

- 自动采用项写入 `pmw-run event --type decision` 或最终输出的“已自动采用”。
- 停止门槛写入 `pmw-run event --type gate` 或 `pmw-run event --type evidence`。
- 用户拍板写入 `pmw-log question` 和 `pmw-log decision`。
- 原型偏好写入 `pmw-log taste`，方案评分写入 `pmw-prototype-board score`。

自动决策不是替用户做主，而是把低风险默认项处理掉，把真正会改变产品结果的选择留给 PM。
