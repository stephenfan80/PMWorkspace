# PMWorkspace v0.1.35

## Summary

Image output now uses an explicit page-mode decision from the locked brief. After a brief is locked, PMW defaults to three-page experiment mode unless the user explicitly asks for one page. When online screenshots are provided, PMW treats them as the base image and requires local A/B/C edits instead of redrawing the full page.

## Changes

- Added `image_output_mode` to `brief_lock`, with `three_page_experiment` as the default locked-brief mode and `single_page_confirmed` only for explicit one-page requests.
- Updated `pmw-controller next` to show the current image mode and expected page count when entering prototype output.
- Redefined one prototype-board item as one complete page output unit; kept `scheme` for compatibility while adding `output_mode`, `page_variant_role`, and `experiment_hypothesis`.
- Updated readiness and image preflight to read the locked brief mode instead of accepting generic fewer-than-three exemptions.
- Required screenshot-based local experiments to analyze the screenshot information architecture, browse path, and task path before registering output units.
- Required three-page screenshot experiments to use the same `base_image`, `screenshot_edit`, explicit local edit scopes, preserved regions, and meaningful A/B/C experiment differences.
- Added long-page physical output checks so screenshot-based pages keep the original app width while allowing adaptive height.
- Refreshed PMW skill docs, references, eval fixtures, and packaged plugin sources.
