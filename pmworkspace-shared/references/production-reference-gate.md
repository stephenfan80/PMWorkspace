# 线上参考门槛

在产品追问、产品简报和原型出图前使用本文件。它解决一个容易漏掉的问题：新页面不一定是纯新功能。只要页面承接线上流程、结果状态或生产视觉体系，就需要先判断是否要参考线上页面。

## 核心原则

- `现有功能迭代` 必须先拿到当前线上截图、录屏或等价视觉基线。
- `现有功能迭代` 默认做生产基线优先的最小可信改造：先证明当前线上哪里有问题、哪些区域必须保留、哪些区域可以改，再决定是否出图。
- `新页面` 也要判断线上参考需求，不能默认直接出图。
- 如果新页面承接线上流程、结果页、状态页、营销落地页、车系页、表单页、支付/预约/留资流程，或必须保持现有 App / Web 生产样式，就先索取参考截图或录屏。
- 如果用户明确确认“没有线上参考”或“按新页面概念稿推进”，可以继续，但必须在产品简报里标注视觉基线来自假设，不是线上事实。
- 缺少必要线上参考时，不写 image-2 提示词，也不生成原型图。
- 用户在选择某个方案方向后补充截图，只能更新线上参考和视觉基线；不能把“方向已选 + 截图已给”当成产品简报已对齐或可出图。

## 线上基线接收

当用户提供生产截图、录屏或等价视觉基线时，下一步不是自动生成原型，而是先输出一段基线拆解：

```text
线上基线接收：
- 已识别页面 / 模块：
- 当前线上已有优势：
- 当前问题区域：
- 必须保留：
- 可以改：
- 暂不应改：
- 新方案要优于当前线上的理由：
- 仍缺的事实 / 数据：
- 当前需要确认：
```

如果当前线上方案在信息密度、视觉层级、转化入口或信任表达上已经明显优于 Agent 的新想法，PMW 必须指出“线上方案更强”，建议微调或保留，而不是为了出图而重画。不能只因为用户要求优化，就默认生成一个更大的新模块、更重的卡片或更花的视觉方案。

## 需要线上参考的信号

满足任一条件，就把 `线上参考需求` 标记为 `需要`：

- 页面是已有线上流程的下一步、结果页、确认页、失败页、售罄页、超限页或异常页。
- 页面要复用现有产品的导航、标题栏、底部操作、卡片、表单、优惠券、补贴、结果模块或状态标签。
- 页面里的成功、失败、待处理、已抢光、额度不足、资格不符等状态，和线上产品已有状态模式相关。
- 用户提到“线上”“App”“站内”“站外召回”“活动页”“领取页”“结果页”“生产样式”“AutoDesign”“汽车之家”等生产环境线索。
- 原型图要交给设计、研发或业务评审，且会被理解为接近上线方案。

## 可以不需要线上参考的情况

满足以下条件之一，可标记为 `不需要`：

- 这是纯概念探索，不接现有线上流程。
- 用户明确要求完全重新设计，不复用当前产品样式。
- 产品还没有任何线上界面，且用户接受按已确认的设计规范目标或 PMW 默认移动端产品 UI 基线做概念稿。
- 用户已经确认没有可用线上截图，并批准按新页面概念稿推进。

## 参考状态

在产品简报、对齐摘要和原型计划里使用这些状态：

- `已提供线上参考`：用户已提供截图、录屏、Figma、Zoon 页面快照，或等价视觉基线。
- `无线上参考已确认`：用户明确说没有线上参考，批准按概念稿推进。
- `缺失待补充`：判断需要参考，但用户还没提供，也没确认没有。
- `不适用`：纯新概念，不承接线上流程，也不要求生产样式。

平台脚本可用时，已提供的线上参考优先登记为 `browser_evidence` 产物，让 dashboard 和下游技能读取同一份轻量证据：

```bash
pmw-artifact add --kind browser_evidence --title "线上参考：<页面/流程>" --status "已采集" --source-skill pm-brief --path "<截图路径>" --url "<线上 URL>" --summary "<页面任务、视觉基线、交互模式、必须保留、可以挑战>"
```

当线上参考是截图或等价视觉基线时，还要登记 `visual_baseline`，把截图转成出图可执行约束：

```bash
pmw-image-audit baseline --reference "<截图路径>" --register
```

`visual_baseline` 至少包含参考图路径、参考像素尺寸、逻辑宽度推断、目标输出像素、核心字号层级、页面边距、模块间距、底部栏高度和参考优先级。只登记 `browser_evidence` 不足以放行 image-2 prompt。

进入 image-2 前，还要把每个 prototype-board 输出单元写入 `生产基线改动证明`：

```text
生产基线改动证明：
- 生产基线问题：<当前线上具体哪里影响理解、信任、转化或反指标>
- 改动区域：<只改哪些模块 / 字段 / 层级>
- 为什么优于当前线上：<基于截图、数据、用户反馈或 PM 判断的具体理由>
- 保留 / 删除边界：<哪些线上结构必须保留，哪些内容降级、删除或后置>
```

如果只能写“更现代 / 更清爽 / 更好看”，说明改动证明不成立，不能出图。

如果参考缺失、读取失败或权限不足，不创建假证据；使用 `pmw-run event --type evidence` 记录 `线上参考状态：读取失败/待补充`。

## 缺失时的提问

如果判断需要线上参考但材料缺失，用一句话停下来问：

```text
这是新页面，但它承接线上流程或生产样式。请先补充可参考的线上截图/录屏：上一步页面、相似结果页，以及成功、失败、售罄、超限等状态；如果确实没有线上参考，请回复“没有线上参考，按新页面概念稿推进”。
```

如果用户已经给了部分截图，但缺关键状态：

```text
现在有上一步页面参考，但结果状态还缺线上样式。请补充相似的领取成功、失败、售罄或超限页截图；如果线上没有这类页面，我会按新页面概念稿做，并在产品简报里标注这一点。
```

## 产品简报字段

产品简报必须记录：

```text
页面类型：<新页面 / 现有页面迭代 / 不明确>
线上参考需求：<需要 / 不需要 / 待判断>
线上参考状态：<已提供线上参考 / 无线上参考已确认 / 缺失待补充 / 不适用>
承接页面：<上一步页面、入口或来源>
相似线上模式：<相似结果页、状态页、活动页、表单页；没有则写“暂无”>
视觉基线：<线上截图 / 用户确认无参考后的概念稿 / 用户提供设计系统 / AutoDesign / 平台模式库 / PMW 默认假设>
设计规范目标：<用户提供 / AutoDesign / 平台模式库 / PMW 默认假设>
视觉基线状态：<已登记 visual_baseline / 缺目标输出像素 / 缺失待补充 / 不适用>
目标输出像素：<参考图尺寸 + 目标输出尺寸；没有参考时写不适用>
```

如果 `线上参考需求：需要` 且 `线上参考状态：缺失待补充`，产品简报确认状态不能标记为 `已对齐`。

## 示例：通用券领取结果页

“通用券领取结果页”虽然是新页面，但它承接领取页和多车提交流程，还要展示成功、暂无补贴、已抢光、超限等状态。因此在出图前必须先问：

- 有没有现有领取成功/失败/售罄/超限页截图？
- 有没有上一步领取页或活动页截图？
- 有没有相似的补贴、优惠券、线索提交结果页？

如果用户确认没有线上参考，再按“新页面概念稿”生成，并在产品简报和原型计划里写：

```text
线上参考状态：无线上参考已确认
视觉基线：用户确认无线上参考后的概念稿
设计规范目标：按当前产品归属选择用户提供规范、AutoDesign、平台模式库或 PMW 默认假设；未确认前不写 image-2 prompt
```
