# PMWorkspace v0.1.34

## Summary

Product brief confirmation is now a two-stage flow: PMW first creates a candidate brief, then locks it once the user confirms and the brief passes boundary checks. The machine gate no longer reads Markdown status text as the source of truth; the formal source is `brief_lock=locked`.

## Changes

- Added `pmw-controller lock-brief` to atomically run boundary checks, write `brief_lock`, update `latest_brief`, and register the current `product_brief` artifact.
- Added `pmw-controller modify-brief` with `editorial`, `non_boundary_addition`, and `boundary_change` modes.
- Updated controller, dashboard, artifact, and image readiness flow to treat `brief_lock=locked` as the only machine truth for locked briefs.
- Kept Markdown status lines as display-only text for humans.
- Allowed candidate briefs to be saved without over-triggering many small gates; existing-feature visual baseline issues now block brief locking, not candidate brief creation.
- Updated readiness language to show human-readable states such as `简报待用户确认`, `简报边界未通过`, `简报已锁定，可进入原型`, and `简报被实质修改，需要重新锁定`.
- Refreshed PMW skill docs, runtime references, eval fixtures, and packaged plugin sources.
