# 互联网最佳实践检索

在产品简报阶段使用。目标是让 PMWorkspace 借鉴公开互联网产品和 UX 最佳实践，但不把产品追问或产品简报变成长研究报告。

For Chinese users, summarize sources and implications in Simplified Chinese. Keep source names and URLs as-is.

## 触发规则

- 产品简报生成前，默认按主场景做一次轻量检索。
- 检索不增加 `Q` 数量；它只帮助助手推荐 `原型重点`、案例启发和不可照搬项。
- 如果用户明确说不需要搜索，记录 `互联网案例检索状态：未启用（用户要求）`。
- 如果网络或搜索工具不可用，记录 `互联网案例检索状态：检索失败（原因）`，并请用户确认是否重试或批准按现有上下文继续。

## 检索深度

默认检索 3-5 个来源，优先级如下：

1. 权威 UX / 设计系统来源：Baymard、Nielsen Norman Group、Apple HIG、Material Design、web.dev。
2. 与主场景相近的公开产品案例：转化表单、结果页、看板、服务状态页、内容社区、AI 引导流程等。
3. 行业相邻案例：当完全同类案例缺失时，用相同用户任务或相同交互模型替代。

不要复制长文、不要保存全文、不要把来源中的能力当成当前产品已经具备。

## 输出格式

写入产品简报时，互联网案例启发只保留可借鉴原则、不可照搬、对原型影响。参考来源放在支持信息；最佳实践不能覆盖当前 brief、Zoon、线上截图、反指标或不可虚构项。

写入产品简报的用户可见压缩格式：

```text
互联网案例启发：
- 可借鉴原则：<对当前原型有用的 2-4 条原则>
- 不可照搬：<当前产品不能直接采用的做法>
- 对原型影响：<哪些信息应突出、后置或标注不确定>
```

参考来源、检索状态和检索日期只能放在 `支持信息`：

```text
支持信息：
- 互联网案例启发：
  - 可借鉴原则：
  - 不可照搬：
  - 对原型影响：
- 参考来源：<3-5 个来源名 + URL>
- 检索状态：已完成 / 未启用（原因） / 检索失败（原因）
- 检索日期：
```

## 使用边界

- 最佳实践只提供启发，不替代用户业务约束、线上参考截图、数据可用性、当前 brief、Zoon、反指标、不可虚构项和 PM 拍板。
- 如果检索结果与用户提供的生产截图或业务约束冲突，以用户上下文和已确认前提为准。
- 如果搜索结果提示当前承诺风险更高，回到当前 `Q` 或一个必要 `D`，不要直接写入原型。
