# 决策选择题模式

PMWorkspace 遇到会改变产品方向、原型范围、实验口径、用户承诺或交付稿的关键点时，默认使用选择题让 PM 拍板。不要只把问题列出来让用户自由发挥。

## Q / D 边界

选择题是 `D` 拍板，不是 `Q` 诊断。

- `Q` 诊断用于发现事实和澄清问题：具体用户、真实损失、现状替代、主目标、反指标、数据和约束。`Q` 一次只问一个，问完停止等待用户回答。
- `D` 拍板用于选择取舍：承诺口径、方案方向、原型范围、实验口径、线索分发、屏幕数量等。只有上下文足够、不同答案会改变执行时才使用。
- 不要用一组三个 `D` 跳过产品诊断；如果用户答案仍然模糊，先回到 `Q`。
- 不要批量输出多个开放问题或长 md 计划来替代 `Q` / `D` 流程。
- `D` 也必须一问一停；每轮只展开一个完整拍板问题。

## 什么时候使用

- 产品方向会分叉：扩大、收缩、转向、先验证或先上线。
- 用户承诺会影响信任：金额口径、覆盖范围、资格条件、数据真实性。
- 原型会明显不同：流程顺序、信息架构、主入口、屏幕数量。
- 实验口径会影响结论：主指标、反指标、入口、样本、线索分发。
- 交付稿仍有待决策项，且不同答案会改变研发或设计执行。

## 输出结构

中文用户使用以下结构：

```text
D1 - <决策标题>
为什么重要：<一句话说明选错会造成什么>
推荐选择：<A/B/C 中的一个>，因为 <一句话理由>

选项 A：<选项名>
- 适合：
- 风险：

选项 B：<选项名>
- 适合：
- 风险：

选项 C：<选项名>
- 适合：
- 风险：

取舍：<这题本质上在权衡什么>
默认假设：如果你不改，我会按 <推荐选择> 继续。

后续待拍板：D2 <只写标题>、D3 <只写标题>。
```

## 逐题规则

- 一次只展开一个完整 `D` 选择题；问完必须停止等待用户回答。
- 如果待决策超过 1 个，只能在当前 `D` 后用一行轻量队列提示，例如：`后续待拍板：D2 手机号出现时机、D3 信任增强方式`。
- 后续队列只写标题，不展开为什么重要、选项、风险、取舍或默认假设。
- 用户回答当前 `D` 后，先记录最终取舍，再进入下一个 `D`。
- 如果用户回答暴露新的事实缺口，回到一个聚焦的 `Q`，不要继续推进下一个 `D`。
- 只有用户明确说“都按推荐”“全部用默认假设”“后续都按默认”时，才允许批量接受推荐项，并逐条记录每个 `D` 的默认决策。
- 如果用户要求“给我完整概览”，只输出 `D` 标题、取舍主题和推荐项摘要，不输出完整选项块。
- 如果 Codex 原生问题选择工具可用，优先用工具；不可用时使用 Markdown 结构。

## 记录规则

用户回答后，平台脚本可用时记录：

```bash
pmw-log question D1 "<决策标题>" "<推荐选择>" "<用户选择>" "<最终决策摘要>"
pmw-log decision "<决策标题>" "<最终决策摘要>"
```

记录内容必须是脱敏摘要，不写入原始客户材料、token、未脱敏截图或私密 Zoon 正文。

## 示例：通用券拍板问题

```text
D1 - “全品牌可用”的对外口径
为什么重要：口径过大容易形成无条件承诺，用户发现部分品牌不可领时会损害信任。
推荐选择：A，因为它既能表达覆盖面，又保留真实业务边界。

选项 A：参与品牌可领取
- 适合：参与品牌较多，但并非全部在售品牌都有补贴。
- 风险：传播上不如“全品牌可用”强，需要页面解释清楚。

选项 B：全品牌可参与查询
- 适合：希望最大化召回点击，同时把领取结果放到查询后。
- 风险：用户可能觉得只是查一查，领取心智变弱。

选项 C：全品牌都有机会领
- 适合：活动资源非常充足、法务允许高承诺表达。
- 风险：如果实际覆盖不足，投诉和信任损耗最大。

取舍：增长吸引力 vs 承诺真实性。
默认假设：如果你不改，我会按 A 继续。

后续待拍板：D2 至高金额展示方式、D3 多车提交后的线索生成、D4 首轮主实验入口、D5 质量护栏指标。
```
