# product_agent 使用指南

`product_agent` 面向产品想法到产品资产的完整链路：对齐、原型、复审、交付。

## 你可以给什么材料

- 一句话想法、业务目标、用户反馈、访谈片段或客服记录。
- 已有 PRD、竞品链接、线上页面 URL、截图、关键节点截图或 Figma。
- 原型图、设计稿、修改意见、评审意见或交付缺口。

材料不完整也可以开始，但 `product_agent` 会先说明当前缺口会造成什么产品偏差。

## 标准链路

1. 对齐：确认真实问题、目标用户、当前替代、当前损失、主目标、反指标和不可虚构项。
2. 原型：仅在产品简报已对齐后，生成移动端优先、多方案、单图绑定的 image-2 原型方向。
3. 复审：检查原型是否忠实表达产品简报，是否违反事实边界、反指标、线上参考和设计系统。
4. 交付：输出产品设计文档、精简 PRD、实验 / 埋点 / 数据缺口或研发交付材料。

## 反馈方式

- 如果你在看产品简报：指出要改的目标、用户、场景、反指标、范围或不可承诺项。
- 如果你在看原型图：指出方案名、屏幕任务、要改的区域和必须保留的内容。
- 如果你要交付：补充接口、数据来源、埋点、实验标准或现成 PRD；没有也可以留空待补充。

## 什么时候会被阻断

- 缺少会改变产品判断的事实。
- 已有功能迭代缺少当前线上视觉基线。
- 产品简报未确认已对齐。
- 原型把未确认能力画成了已承诺事实。
- 交付文档需要接口、数据或验收口径，但这些信息还没有确认。
