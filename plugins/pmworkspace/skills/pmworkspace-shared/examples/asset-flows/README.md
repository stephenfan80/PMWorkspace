# 资产流样例总览

本目录展示 PMWorkspace 面向用户可理解的四条完整资产链。每条链都用公开、虚构、脱敏内容说明同一件事：一个产品任务不是只生成一张图，而是依次沉淀为下游可以读取的产品资产。

## 资产顺序

| 顺序 | 资产 | 用户怎么理解 |
|---|---|---|
| 1 | `product_brief.md` | 已对齐产品简报，回答为什么做、做什么、不做什么、不能承诺什么。 |
| 2 | `visual_baseline.md` | 线上截图 / 视觉参考基线，仅在已有功能和截图迭代中出现。 |
| 3 | `prototype_manifest.md` | 原型清单，记录每个方案、屏幕、目标、反指标、不可虚构边界和生成状态。 |
| 4 | `prototype_review.md` | 原型复审结论，判断可通过、需要重出、需要补参考或需要 PM 拍板。 |
| 5 | `handoff.md` | 产品设计文档、精简 PRD 或研发交付稿。 |

## 四条样例

| 样例 | 说明 | 重点 |
|---|---|---|
| [`01-new-idea`](01-new-idea/) | 从“习惯匹配”新想法到产品设计文档。 | 新想法如何先做产品判断，再出 3 条产品路径。 |
| [`02-existing-feature`](02-existing-feature/) | 从订阅取消页生产截图到优化交付。 | 已有功能必须先有视觉基线，不能隐藏取消入口。 |
| [`03-screenshot-iteration`](03-screenshot-iteration/) | 根据标注截图改一张已生成原型。 | 只改指定区域，产品承诺变化必须回写 brief。 |
| [`04-prd-handoff`](04-prd-handoff/) | 从课程试听报名流程到精简 PRD。 | PRD 读取 brief、manifest、review，不虚构接口和埋点。 |

## 阅读方式

先读每个样例目录的 `README.md`，再按资产顺序阅读。样例中的图片路径、数据、指标、用户和业务背景都是虚构的；真实项目必须读取当前 run 的本地资产、Zoon 快照、截图和用户确认。
