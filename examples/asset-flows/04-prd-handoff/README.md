# 样例 04：从转化流程到精简 PRD

这是一个真实匿名风格的公开样例，展示 PMWorkspace 如何把课程试听报名流程从产品简报、视觉基线、原型清单、复审结论整理成精简 PRD。

## 匿名背景

某教育产品想优化试听报名。当前报名页过早要求用户留手机号，用户在提交前不确定课程是否适合自己的水平；团队需要一个能交给研发评审的精简 PRD。

## 用户输入材料

```text
使用 $pm-workspace 为课程试听报名流程生成 3 个移动端方向，对齐后整理成精简 PRD。
用户问题：学员在留下联系方式前，想知道课程是否适合自己的水平。
目标：提升试听预约完成率。
反指标：避免低意向预约和投诉风险。
已知数据：课程等级、课程大纲、老师可约时间、试听片段。
输出：报名页、预约结果页、精简 PRD。
```

已提供：课程等级、课程大纲、老师可约时间、试听片段这些能力线索。
未提供：留资接口、预约状态枚举、试听片段授权口径、埋点属性。

## 资产流

1. [`product_brief.md`](product_brief.md)：转化流程的已对齐产品简报。
2. [`visual_baseline.md`](visual_baseline.md)：没有生产截图时，记录默认移动端转化流程基线。
3. [`prototype_manifest.md`](prototype_manifest.md)：登记 3 条转化路径。
4. [`prototype_review.md`](prototype_review.md)：判断推荐方案和待补能力。
5. [`handoff.md`](handoff.md)：读取上游资产生成精简 PRD。

## 关键 PM 判断

- 这不是“把表单做短”这么简单，而是要先给足够价值交换。
- 报名前可展示试听片段和等级匹配，但不能承诺老师立即确认或保证学习效果。
- PRD 只写核心字段：背景、价值、方案、功能、接口数据、埋点、实验、待补充、不可虚构。

## 脱敏边界 / 不能照搬

- 样例里的接口和埋点是占位，需要真实研发确认。
- 不能把缺失接口写成已具备。
- 不能补写测试计划、周期、人力和排期，除非用户明确要求。
