视觉基线：`visual_baseline.md` / 已登记
画布：`physical_longboard`，目标 `1179 x >=2556`
输出规则：一个方案 + 一个屏幕 = 一张 image-2 图

## 输出单元

| 方案 | 屏幕任务 | 主目标 | 反指标 | 状态 |
|---|---|---|---|---|
| A 差异解释前置 | 优化后取消页 | 减少误取消。 | 取消入口清晰可见。 | 计划生成 |
| B 状态结果透明 | 取消确认结果页 | 让用户理解取消后状态。 | 不制造挽留压力。 | 计划生成 |

## 方案 A：差异解释前置

- 产品路径：相信误取消来自用户不知道暂停和取消的后果。
- 用户行为假设：用户理解差异后，会选择更符合意图的动作。
- 要赢过的现状替代：直接点取消后再反悔。
- 当前损失：误取消和客服解释成本。
- 删除 / 牺牲 / 后置项：不做优惠挽留，不加长问卷。
- 编辑范围：解释模块、按钮文案、局部层级。
- 保留区域：账号导航、订阅主体信息、取消入口。
- 反指标保护：继续取消入口必须可见。
- 不可虚构边界：不展示折扣、不展示人工回访。

## 方案 B：状态结果透明

- 产品路径：相信用户取消后最担心的是“什么时候生效、还能不能恢复”。
- 用户行为假设：明确状态能减少投诉和反复操作。
- 要赢过的现状替代：取消后不知道会员何时结束。
- 当前损失：状态不确定导致客服咨询。
- 删除 / 牺牲 / 后置项：不在结果页继续强挽留。
- 编辑范围：结果页状态说明、恢复入口、服务截止时间。
- 保留区域：成功状态、订阅信息、返回账号入口。
- 反指标保护：不承诺不支持的恢复政策。
- 不可虚构边界：不展示一键退款或价格保留。

## 方案 C：暂停路径清晰

- 产品路径：相信一部分用户不是要离开，而是短期不用。
- 用户行为假设：解释暂停时长和恢复方式后，用户会选择暂停。
- 要赢过的现状替代：为了暂时不用而取消。
- 当前损失：可保留用户被误导到取消。
- 删除 / 牺牲 / 后置项：不做个性化优惠，不做客服介入。
- 编辑范围：暂停说明、暂停 CTA、继续取消二级入口。
- 保留区域：依法取消入口仍可见。
- 反指标保护：继续取消不能藏在折叠或灰色弱按钮里。
- 不可虚构边界：暂停时长必须来自业务确认。
