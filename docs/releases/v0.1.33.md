# PMWorkspace v0.1.33

## Summary

Runtime recovery and readiness diagnostics hardening. This release keeps the PMW hard gates strict, but makes them resumable, diagnosable, and recoverable when users answer a pending gate with a short confirmation.

## Changes

- Added shared runtime identity helper `bin/pmw_runtime.py`.
- Added `pmw-controller answer` for pending gate replies without creating a new task revision.
- Added structured confirmation fields: `confirm_state`, `confirm_subject`, `subject_revision`, `gate_id`, and `confirmed_by_event_id`.
- Added `pmw-controller confirm-brief` to atomically set latest brief, write brief confirmation, and register current `product_brief`.
- Updated `--run` stamping in `pmw-run`, `pmw-artifact`, `pmw-prototype-board`, and `pmw-image-preflight` to use the target run `task_intake` snapshot.
- Added readiness `diagnostics` with expected context, candidate context, mismatch matrix, first blocker fingerprint, and recovery command.
- Added repeated preflight failure budget: same blocker fingerprint fails twice as `RECOVERY_REQUIRED`.
- Quarantined legacy mixed context as candidate-only evidence.

## Validation

- Added P0 eval fixtures for short answer recovery, run snapshot stamping, structured confirmation, atomic brief confirmation, readiness diagnostics, failure budget, and image permit recovery e2e.
- Syntax check target: `python3 -m py_compile bin/pmw_runtime.py bin/pmw-controller bin/pmw-dashboard bin/pmw-artifact bin/pmw-run bin/pmw-prototype-board bin/pmw-image-preflight`.
- Release validation target: `bin/pmw-eval run --suite full`.
